# Project report 内容审阅

审阅日期：2026-10-28。对象：`fastclaw_project_report.md` 当前原稿；下列行号对应本次审阅前版本。此次为内容审阅，没有修改原稿、重新运行实验或改动封存结果。对关键工程论述检查了当前代码，对主要实验数字检查了归档结果；不是对全部历史运行重新审计，也不是 Word 排版验收。

## 总体判断

报告的核心定位基本成立：介绍 agent runtime 的工程实现，以执行模式比较和金融工作流展示已验证的能力及局限。现有材料足以继续整理报告，不需要为修正文稿问题扩大实验规模。

主要缺陷是：少数工程机制描述不准确；早期文本评测与后续真实状态修改的措辞混用；方法章节保留了未在结果章节呈现的指标；历史问题、当前修复与剩余限制没有完全区分。并非主要实验数字整体错误，也不意味着已有应用案例全部失效。

## 一、优先修改：技术机制与证据边界

### 1. 原生插件的进程边界前后矛盾

- 位置：III A，第 116 行；III E，第 155 行。
- 前文说 native plugins 和核心可以共享 host process，后文说原生插件以 subprocess 运行。
- 代码依据：`internal/plugin/process.go:68` 使用 `exec.CommandContext` 启动插件进程。
- 建议：明确核心内置工具可以在 runtime 进程内执行；原生插件为同一主机上的独立子进程，通过标准输入输出交换 JSON-RPC；MCP 和 sandbox 另有其部署边界。不要混淆 host machine 与 host process。
- 影响：这是架构与隔离边界的实际表述错误，应优先修正。

### 2. `done` 事件不能当作成功或最终答案已持久化的充分证据

- 位置：IV D，第 238 行，以及其他将流结束与成功相连的概括。
- 原文称 `done` 只会在最终 assistant 消息持久化后发出。
- 代码依据：`internal/agent/events.go:128–143` 的错误路径也发出 `error` 后发出 `done`；预算/迭代耗尽还可以产生不完整终态后结束流。
- 建议替换为：成功路径在最终消息持久化后结束流；`done` 本身表示流已结束，成功与否还需结合错误事件、终态代码和持久化结果判断。
- 影响：否则读者可能误以为“收到 done”就证明工作流完成，而这恰好是本项目评测需要区分的事情。

### 3. 超时的作用范围与终止保证写得过强

- 位置：III C，第 139 行；IV G，第 270 行。
- 实现不是一个覆盖全部排队和执行阶段的 queue-wide deadline：`internal/taskqueue/queue.go:256–306` 先等待准入，再按统一配置为当前任务创建执行超时。
- 处理函数同步接收 context；取消依赖下游操作配合，不能仅凭 context timeout 推导任意阻塞操作必然停止。
- 建议：写成“共享配置的逐任务执行超时在准入后启动；排队阶段响应请求/队列取消；执行期限依赖下游遵守取消”。迭代上限约束循环次数，不等价于任意调用的墙钟时间保证。
- 影响：修正文稿的保证范围；这不是在断言已经观察到生产死锁。

### 4. 文本验收与实际账本动作必须使用不同措辞

- 位置：V H、VI F，以及 Appendix A 第 865 行的 “Thesis review executed once”。
- 报告已经说明早期固定证据实验没有调用财务工具、没有修改账本，但案例表又使用“一条告警、计数变为 2、执行一次 review”等已执行口吻。
- 建议：早期实验统一标为“答案应表达的策略/预期状态变化”，不要称为实际执行；真实落库证据只归入后续 tool-backed panels。
- 影响：防止把回答说对了误写成系统实际做对了。无需删除早期校准实验，只需划清证据层级。

## 二、重要修改：方法、结果与结论对齐

### 5. 方法章节承诺展示的指标多于结果章节实际展示的内容

- 位置：VI C 第 431 行、VI H 第 511 行，与 VII B 第 566–594 行。
- 方法称报告记录 pass@1/pass@k、consistency、P50/P95、tokens per successful run 等，并将原始配对表称为 primary result；主实验结果实际主要呈现严格通过数、均值、token 和费用，未完整呈现上述项目。
- 调度测试中的 P50/P95 不等于 SEC 模型实验的 P50/P95。
- 建议优先精简方法，区分“harness 可保存的指标”与“本报告实际分析的指标”。若某项指标确有必要，再从已有归档补表，不必补跑实验。

### 6. Raw-context 与 shared-retrieval 不是只改变压缩长度的单变量实验

- 位置：VI G 第 500 行 “isolating the effect of retrieval compaction”。
- 两者还改变了检索调用阶段、证据选择和模型输入；因此差异不宜完全归因于上下文压缩本身。
- 建议：改称比较“完整原文输入与共享检索策略的整体权衡”。可以报告资源、延迟和完成率差异，但不要声称严格隔离了压缩机制的因果效应。
- 同理，控制调用次数不是所有架构比较的必要前提；调用次数有时本身就是架构产生差异的机制，应披露而不是机械地要求相等。

### 7. 超时配对不能与正常完成的速度比较混为一谈

- 位置：第 578 行 “faster ... all 72 assigned pairs, including ... timeout pairs”。
- 结果表已正确把 Solo 两次超时排除在完成延迟均值之外，但后续又把它们放进“全部配对完成更快”的概括。
- 建议：分别写 70 个双侧完成配对的延迟结果，以及另外 2 个 Team 完成而 Solo 超时的配对。超时观测可用于完成性判断，不提供 Solo 的实际完成时间。

### 8. 历史状态展示问题、当前修复、下游约束尚缺三者没有说清

- 位置：VII E 第 705 行；VIII C 第 743 行；IX C 第 826 行。
- 结果章节已写 serializer 后续将初步研究标为 research-only；后文仍直接称 “unblocked price-only thesis”。
- 当前 `plugins/finance-tools/plugin.py:1856` 起按 hold/status 输出 blocked、research_only 等标签。标签改正不等于所有下游消费路径都实现强制决策禁用。
- 建议：固定为三句话：原观测出现了什么；后续哪些展示/序列化问题已修；哪些下游强制约束仍未验证或未实现。不要把已修问题写成当前完全未修，也不要把标签修复写成端到端权限保障。

### 9. Skill 数据获取与职责表的排他式描述不一致

- 位置：V F 第 361 行；V C 与 VII E 的在线案例。
- 表格把 data retrieval and normalization 只分配给 typed finance tool，但在线案例实际通过 Skill 指导通用执行工具运行取数脚本，再通过财务插件写入账本。
- 建议：将取数实现写成“typed tool 或 Skill 指导下执行的确定性脚本”；Skill 负责流程知识和脚本入口，真正执行仍受 runtime 的工具和权限控制。

### 10. 讨论中出现了结果章未交代的四案例初始实验

- 位置：VIII B 第 731 行，与第 597–600 行。
- 讨论说简单初始套件被四种模式全部通过；结果章主要介绍六案例确认实验，其中三种模式 5/6、另一种 4/6。
- 归档 `2026-08-02-pilot-r7-summary.md` 确有另一个四案例、四模式均 4/4 的历史实验，因此不是数字造假，而是缺少衔接。
- 建议：要么在结果章补一句明确这是另一轮四案例初始校准，要么删除此段关于饱和实验的比较，避免读者误认为是在描述六案例实验。

### 11. 模型与运行配置还不够自包含

- 位置：VI G、VII B 等仅用 Pro/Flash 的地方。
- Pro/Flash 不是独立可识别的模型标识；归档记录可见具体 provider/model alias。
- 建议加入一张简短配置表，从归档照录提供方、模型标识、角色分配、关键输出/超时限制、运行和代码快照日期。无法从档案确定的设置不要补写默认值。
- 后续补丁不应默认为早期运行已使用，静态测试统计也应标明所属快照。

## 三、较小的逻辑与编辑问题

### 12. 选择 semaphore 的理由不应声称天然优于 worker pool

- 位置：第 145 行。
- 相同并发上限下，长任务都可能占用执行容量；worker pool 并不天然比 semaphore 多一个跨会话队头阻塞问题。
- 建议保留工程选择理由——与 per-chat FIFO、取消传播和 root admission 的组合更直接——删除未经对照证明的性能优越性表述。现有负载测试并未比较这两种设计。

### 13. 研究问题从 RQ2 开始，缺少 RQ1

- 位置：第 82–98 行及后续总结。
- 将前两项改为 VP1/VP2 后仍保留 RQ2/RQ3，导致独立阅读像漏了一项。
- 建议统一为 RQ1/RQ2，或直接使用“执行模式权衡”“工作流可用性”等短标题。不需要重新放回缩略语表。
