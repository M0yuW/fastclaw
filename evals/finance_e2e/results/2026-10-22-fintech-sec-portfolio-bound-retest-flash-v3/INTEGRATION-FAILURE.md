# Bound tool not exposed by initial Gateway binary

This first v3 execution is a retained **integration failure**, not a content-quality pass. The Python finance-tools plugin had `portfolio_policy_bound`, but the Go `finance-workflow-pilot` policy allowlist in the Gateway binary did not yet allow that name. The model's attempted call returned `Unknown tool: finance-tools__portfolio_policy_bound`; later outputs often called the existing `portfolio_risk` with `holdings_complete=false`, which correctly refused an exact calculation. All 10 raw observations remain `needs_review`. Estimated model cost was USD 0.0135882712, with clean priced request traces but no valid bound-tool result. The failure is not a DeepSeek timeout, SEC-source error or evidence that the deterministic bound itself was wrong.

Afterward, the policy allowlist and its Go test were updated, a new Gateway binary was built, and the same frozen protocol ran into a separate `...-v3-policy-fix/` directory. Do not recode or delete these initial observations, and do not pool their content labels with the successful tool-exposure arm. `RESULT-SHA256.txt` locks this directory's manifest and ten raw result files.
