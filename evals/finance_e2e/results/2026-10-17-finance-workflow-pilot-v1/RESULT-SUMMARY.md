# Four-workflow finance pilot (exploratory)

This is a feasibility pilot, not a confirmatory reliability estimate. Four neutral-ID workflows ran against separate Gateway homes, model sessions, and finance SQLite ledgers. The isolated agent used the `finance-workflow-pilot` allowlist: it could invoke research review, screening, and risk tools, but not shell execution, direct network tools, event ingestion, or trading. Trusted fixture setup performed event ingestion. P01/P02 use SHA-256-locked SEC source artifacts; P03/P04 use explicitly synthetic, deterministic Finskills-compatible scripts because the external Finskills scripts are not present in this repository. The plugin marks their source as `local_evaluation_fixture`, not as live market data.

| Workflow | Pilot path | Mechanical result | Independent content check |
|---|---|---|---|
| P01 — sequential events | AMD Q2 thesis → Q3 event/review → duplicate Q3 ingestion → Q4 event/review | Pass: two distinct linked reviews, two version increments, duplicate suppressed, both alerts acknowledged | Q2→Q3 and Q2→Q4 values and period labels were consistent; Gaming risk remained visible. |
| P02 — incomplete packet then supplement | NVIDIA Q1 thesis → incomplete Q2 packet → complete Q2 packet with distinct packet identity | Pass: first review `needs_review`, missing gross margin recorded, second linked review after completion, two version increments | Model changed the source baseline revenue from 26,044 to 26,040 USD million in both written reviews, yielding +15.4% instead of the source-derived +15.3% revenue growth. The state guard did not catch this prose/calculation error. This tested missingness and supplementation, not two genuinely conflicting primary sources. |
| P03 — screen to candidate thesis | Synthetic FICA/FICB screen → completeness gate → FICA thesis | Pass: `screen_stocks` and `thesis_save` called; FICB rejected for absent free cash flow; no FICB thesis | Final response listed FICA's metrics, but the persisted thesis contained only generic completeness wording rather than the actual numeric screen metrics. Persistence succeeded but evidence detail was lost at the application/model layer. |
| P04 — portfolio concentration to human review | Synthetic 70% FICA / 30% FICB → deterministic concentration diagnostic | Pass: `portfolio_risk` called, 70% versus 50% limit explained, no ledger mutation or trade tool | The 20-percentage-point breach and HHI 0.58 matched the synthetic fixture; model recommended human review only. |

Across six model-backed turns, all four workflows passed the prespecified mechanical checks without request or provider error. There were 21 priced model calls, 78.737 seconds of summed Gateway wall time, and USD 0.024791 in frozen-price estimated model cost, not a provider invoice. The USD 0.10 stop did not trigger. Independent SQLite inspection found P01/P02 each with one thesis, two reviews, and two alerts; P03 with one thesis and no review/alert; P04 with no ledger records. `manifest.json` records source, fixture, plugin, policy, binary, and template-DB hashes; all matched after the run. No credential was found in the saved JSON/Markdown artifacts, and the isolated port was closed afterward.

Interpretation: the runtime can execute these four *bounded, configured* workflow shapes with policy-filtered tools and inspectable state. The pilot does not establish live screening/risk data availability, autonomous SEC retrieval, robust handling of genuinely conflicting primary sources, statistical reliability, or high-quality financial insight. The two content defects show why source-grounding and persisted-record checks must be scored separately from tool/state completion. Do not pool these four heterogeneous cases into a success-rate claim for real-world financial analysis.
