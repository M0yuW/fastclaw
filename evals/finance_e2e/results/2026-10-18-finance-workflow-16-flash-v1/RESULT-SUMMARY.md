# Sixteen-case Flash finance workflow panel (exploratory)

Sixteen distinct cases were run once each in the frozen order in `manifest.json`: four source-locked SEC event-to-thesis cases (E), four synthetic source-consistency cases (C), four synthetic stock-screening cases (S), and four synthetic portfolio-concentration cases (P). Every case used a fresh Gateway home, session, and finance ledger. Preflight checked SEC fact IDs and source locks and exercised the synthetic plugin fixtures without model calls. The raw per-case responses and ledger copies are retained without rescoring.

| Workflow | Cases | Frozen mechanical passes | Notes |
|---|---:|---:|---|
| SEC event → thesis review | 4 | 4 | Source packets, stored values, review links, missing-metric guard and alert transitions passed. E3's narrative nevertheless claims downstream decisions are blocked, while the stored thesis reports `actionability=available`. |
| Source consistency → research state | 4 | 3 | C1 agreement and C2 unresolved conflict completed; C4 absent primary evidence produced `needs_review`. C3 formal-correction case stopped after a malformed model-generated `thesis_record_review` JSON argument; no review was written and the alert remained new. |
| Screen → candidate thesis | 4 | 3 | S2/S3/S4 did not create an unsupported thesis. S1 also declined to create one, but the frozen oracle expected a preliminary synthetic thesis; its refusal is defensible because the fixture lacks filed evidence and period/units. Count this as an **oracle-design ambiguity**, not established model error. |
| Portfolio concentration | 4 | 3 | Complete portfolios at 45%, 50%, and 65% top weight were handled correctly. P4 called the risk tool with only the known 45%/30% holdings; the fixture silently renormalized them to 60%/40% and returned a false breach. The agent identified and rejected that result in its final answer, but the tool-call safety check failed. |

Total: **13/16 frozen mechanical passes**, 54 Flash model calls, 46 paired finance-tool calls/results, and estimated model cost **USD 0.0170542848** under the frozen price table (not a provider invoice). One model call in C3 is flagged `cost_uncertain=true` despite `priced=true`, so the total is an estimate with that explicit uncertainty. There was one trace-level error, in C3. No HTTP/provider request error or model mismatch was recorded. The runner checked `priced` but did not stop on `cost_uncertain`; future runners must check both. These cases are selected, mostly synthetic, and each has only one observation; the count is not a population reliability estimate or proof of financial-insight quality.

The post-run review found two important distinctions hidden by the pass count. First, C3's response had a trace `error` for invalid tool-argument JSON but the HTTP response ended with a generic apology; the current frozen mechanical checker did not explicitly inspect trace errors, although the case failed on missing state transitions. Second, E3 recorded `needs_review` but did not set the ledger's `decision_hold`; the narrative statement that downstream decisions were blocked is not supported by stored state. An eventual report should separate narrative caution from an enforced runtime guard.

Priority follow-up before a confirmatory panel: reject or explicitly mark incomplete portfolio weights before normalization; expose a typed trace/terminal failure for malformed tool arguments and budget exhaustion; align the S1 oracle with its cautious prompt and synthetic-only evidence; and add an assertion comparing any claimed decision hold with actual ledger `actionability`. Do not treat corrected or repeated runs as replacements for this frozen exploratory panel.
