# Prospective cross-workflow holdout frame v1

This frame was created after the AFRM/SOFI/UPST engineering pilots. Those issuers and all tickers listed as development exclusions are **not** fresh validation cases. The machine-readable universe and selection seed are in `prospective_cross_workflow_frame_v1.json`; `rank_prospective_cross_workflow_v1.py` ranks candidates by SHA-256 within four business strata. Five of six candidates per stratum are primary (20 independent issuer clusters); the sixth is a reserve, usable only for a documented, source-eligibility failure. Model quality or workflow outcome is never an exclusion criterion. This is a sampling frame, not a completed experiment. Candidate ticker-to-CIK identities were checked against the SEC's public ticker file before the first model call; CIK, not a mutable trading symbol, is the source-discovery identity.

## Source and case freeze before model calls

For each primary issuer, use the two latest *adjacent reported fiscal quarters* whose earnings releases were filed by 2025-12-31 as SEC 8-K EX-99.1 artifacts. Record CIK, accession, filing date, fiscal period, exact artifact URL, local byte hash, row/column locator, unit and accounting basis. An issuer is ineligible only if no such pair or no common material measure exists; log the reason and replace it with that stratum's pre-ranked reserve. If a reserve is also ineligible, report the shortage and do not quietly choose another issuer. Source lookup and fact extraction may reveal issuer-specific traps, but prompts, numeric oracles and risk checks must be frozen before any answer from that case is generated.

Discovery addendum, still before this arm's first model output: SEC Item 2.02 filing dates are used only to shortlist a *provisional* pair (newer filing first, 55–130 calendar days apart, both with a single EX-99.1). This is not a substitute for reading the exhibits' actual fiscal-period labels. A failed period/basis check must be logged and the next pair tested under the same original source rule. FOUR's 2025 Q2 filing has EX-99.2, not EX-99.1; its latest two calendar filings cannot automatically form an eligible pair. This exception is retained rather than silently broadening the attachment rule.

The 20-issuer frame directly supports 20 distinct **single-issuer event → thesis review** clusters. It can also supply source material to screen → candidate and portfolio-risk workflows, but a multi-issuer screen or portfolio is a *case packet*, not one issuer. Reusing the same 20 issuers across many overlapping packets does **not** create 20 independent clusters in either of those workflows. For portfolio cases, make weights, aggregation status, unknown sleeves and alert limits explicit. Do not imply real user holdings or trade execution. A workflow may legitimately defer when evidence is insufficient; that is not a quality failure if it is accurately justified and the ledger reflects `needs_review` or an equivalent non-actionable state.

## Observation and adjudication rules

Run five fresh sessions and isolated ledgers per issuer/workflow under one frozen model, runtime, prompt, tool set and budget. Preserve failed and timed-out calls in the denominator; no outcome-based retries. Score execution/state, source and calculation correctness, inference discipline, counterevidence/risk coverage, and research utility separately using `INSIGHT-QUALITY-HOLDOUT-RUBRIC-v2.md`, frozen before this arm's first model output. Each material conclusion requires a source/fact pointer or an explicit uncertainty label. A host-computed number is not proof that the prose interpretation is sound. Contradictory or unassessable claims do not count as high quality. Review all responses at claim level; LLM-as-judge is diagnostic, not an independent human gold standard.

The predeclared descriptive case gate remains: all five runs pass execution and fact gates; all have no critical error; and at least four of five receive `high_within_case` under the frozen F/I/R/S/U rubric. One noncritical `adequate_within_case` run is permitted, but `problematic` or `not_assessable` is not. Report case-level outcomes by workflow rather than treating 100 correlated answers as 100 independent cases. Twenty all-success **independent case packets** in each workflow would exceed the predeclared Bonferroni-adjusted one-sided 95% exact lower-bound threshold of 80%; failures require more cases and may falsify the planned claim. The current 20-issuer frame reaches this candidate count only for the single-issuer event workflow. A comparable multi-issuer screening or portfolio claim requires its own source-disjoint packet frame (for example, 20 three-issuer packets require 60 issuer events) or a dependence-aware analysis that does not pretend repeated issuers are independent. This arithmetic assumes the selected cases are meaningfully exchangeable with their stated candidate universe, not every financial application. No paid model run is authorized merely by this frame; spending and call caps must be checked before execution.

## Claim boundary

Even a passing panel could support only repeatable, source-bounded decision support across these tested financial workflows. It would not prove profitable investment advice, superiority to an analyst, or the subjective market value of insights. A blinded finance-domain human review remains unavailable and should not be replaced by self-scoring.
